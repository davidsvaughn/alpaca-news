in the folder 'finscore-api' I want you to do the following...  

Add code for serving a fine-tuned model as a FastAPI endpoint.  

Use the file 'ft/test_signal.py' as a guide.  
This illustrates the basic usage of the actual model, and shows the functionality I want emulated in the FastAPI endpoint.  

The model is one that I custom fine-tuned and am now serving with this command:  

```
sudo docker run --gpus all \
    -e "HUGGING_FACE_HUB_TOKEN=$HUG_READ_TOKEN" \
    -v ~/.cache/huggingface:/root/.cache/huggingface \
    -p 8080:8000 \
    --ipc=host \
    vllm/vllm-openai:latest \
    --model davidsvaughn/finscore-W4A16 \
    --max-num-seqs 1 \
    --max-model-len 2048 \
    --max-num-batched-tokens 32 \
    --gpu-memory-utilization 0.2
```

In the 'finscore-api/api' folder I have created empty files that you need to fill in.  These are for the FastAPI endpoint.  
I want to be able to submit **just the article** to the endpoint, and then the FastAPI endpoint will take care of rendering the prompt (I've copied to 'finscore-api/api/signal_prompt.md') and also computing the expected score from logprobs (see 'ft/test_signal.py' for clarification).  

You will also need to fill in 'finscore-api/compose.yml' so that when the user runs `docker compose up -d` this will start 2 docker containers...  
one for serving the vllm model
and the other for serving the FastAPI endpoint, which then calls the vllm model

Add some extra lines in 'finscore-api/compose.yml' (commented out) that makes it easy to switch to serving the 'davidsvaughn/finscore-W4A16' model if it is stored locally somewhere else on the machine (instead of HF cache).

Here's an example 'finscore-api/compose.yml' (from a different project):
```
services:
  vllm:
    image: vllm/vllm-openai:latest
    command: [ "--model", "/models/essay-flagger-W4A16" ]
    # command: [ "--model", "davidsvaughn/flagger-W4A16" ]
      # - --model
      # - /models/essay-flagger-W4A16
      # optionally pin max model workers, GPU memory util, etc:
      # - --max-model-len
      # - "4096"
    # ports:
      # vLLM serves on 8000 in the container; keep it internal by not publishing,
      # OR publish if you want to hit it directly. Here we keep it internal.
      # - "8080:8000"
    deploy:
      resources:
        reservations:
          devices:
            - capabilities: ["gpu"]
    # environment:
    #   # Optional; speeds downloads the first time
    #   HUGGING_FACE_HUB_TOKEN: ${HUG_READ_TOKEN:?set in shell}
    volumes:
      - /home/azureuser/models:/models
      # - ~/.cache/huggingface:/root/.cache/huggingface
    ipc: host

  api:
    build:
      context: ./api
      dockerfile: Dockerfile
    depends_on:
      - vllm
    ports:
      - "8001:8001"  # expose only the API
    environment:
      # API_KEY: change-me
      # Ensure the API calls the *service name* on the Docker network
      VLLM_URL: http://vllm:8000/v1/chat/completions
      # Make sure PROMPT_FILE points to the file *inside the image*
      PROMPT_FILE: /app/prompt.md
      HOST: 0.0.0.0
      PORT: "8001"
      YES: "1"
      NO: "0"
      MAX_TOKENS: "2"
      TEMPERATURE: "0"
      TIMEOUT: "30"
      # TOP_LOGPROBS: "6"   # uncomment for default top_logprobs
    restart: unless-stopped
```
